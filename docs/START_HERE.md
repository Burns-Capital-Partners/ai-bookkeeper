The owner should be able to return after months away and know where things stand. An authorized agent should be able to continue without the original conversation.

## Two places to remember

**This repository** contains the common process, worker, tests and blank templates. Use its current main revision; old downloaded guides are dated reference copies. It contains no real property ledger, credentials or tenant information.

**Two short private documents per entity:** `STATUS.md` is the bookmark: completed and verified work, current position and next actions. Linked `CONTEXT.md` explains the books to the owner/CPA: standing facts, accounting treatment and open decisions. Keep the summary to about 200–300 words and context to about one page. Detailed evidence and technical history stay behind links. See the [record contract and templates](ENTITY_RECORD.md).

The approved shared drive is the filing home. Read its `00) Start Here` guide, then create or reuse the [Bookkeeping layout](DRIVE_FILING.md) for each entity. Statements are filed by institution/source and year, reports by year, and worker evidence separately. `STATEMENT_INDEX.md` links saved sources and flags actual coverage gaps. Maintain this same structure on every later visit.

## Give this to an agent

**New entity**

> Follow this repo's implementation guide for [entity] using [approved private folder]. Read the shared drive's 00) Start Here guide and existing answers/sources first. Complete docs/DRIVE_FILING.md: create or reuse the Bookkeeping folders, navigation and statement index; preserve the existing STATUS.md and CONTEXT.md using the entity-record templates only where missing. Batch missing factual questions and present real decisions with options. Verify source coverage before migration, use the smallest supported adaptation, and lead the authorized work through an accepted month and periodic-operation checks. Close the session using the improvement loop.

**Existing books**

> Resume [entity] from [private STATUS.md link] using this repo. Read the drive's Start Here guide, current summary, standing context, statement index and open queue; check the evidence needed for the next action. Preserve completed work and published entries. Reuse the filing layout in docs/DRIVE_FILING.md and update the same index as records change. Continue within recorded authority, batch the questions that actually need me, then update the same concise status document, refresh owner/CPA context when facts changed, and verify shared readback. Report only the result, remaining issues and next action.

**A process improvement**

> Capture what slowed or broke this run. Keep private accounting facts in the entity record. Turn reusable lessons into the relevant checklist or a tested code change in this repo. Record the commit and whether each entity has adopted it. Do not call a documented idea an implemented or deployed feature.

These prompts do not grant access, authorize new ledger changes or create a background executor. Use the entity's existing authority and verify the actual tools. Keep one lead and one ledger writer.
