# Start or resume the bookkeeper

The owner should be able to return after months away and know where things stand. An authorized agent should be able to continue without the original conversation.

## Two places to remember

**This repository** contains the common process, worker, tests and blank templates. Use its current main revision; old downloaded guides are dated reference copies. It contains no real property ledger, credentials or tenant information.

**One private `STATUS.md` per entity** is the living entry point. It links to the official Zoho organization, evidence, decisions, access instructions and actual runtime. Reuse an existing status file and its URL. Its first screen says what is complete and what needs attention; detailed historical notes belong in a linked archive. See the [record contract and template](ENTITY_RECORD.md).

## Give this to an agent

**New entity**

> Follow this repo's implementation guide for [entity] using [approved private folder]. Read existing answers and sources first. Establish one STATUS.md using the entity-record template. Batch missing factual questions and present real decisions with options. Verify source coverage before migration, use the smallest supported adaptation, and lead the authorized work through an accepted month and periodic-operation checks. Close the session using the improvement loop.

**Existing books**

> Resume [entity] from [private STATUS.md link] using this repo. Read the current summary, standing context and open queue; check the evidence needed for the next action. Preserve completed work and published entries. Continue within recorded authority, batch the questions that actually need me, then update the same status document and read it back. Report only the result, remaining issues and next action.

**A process improvement**

> Capture what slowed or broke this run. Keep private accounting facts in the entity record. Turn reusable lessons into the relevant checklist or a tested code change in this repo. Record the commit and whether each entity has adopted it. Do not call a documented idea an implemented or deployed feature.

These prompts do not grant access, authorize new ledger changes or create a background executor. Use the entity's existing authority and verify the actual tools. Keep one lead and one ledger writer.
