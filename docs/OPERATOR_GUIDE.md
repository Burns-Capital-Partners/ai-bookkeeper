# When you return to the books

You should not need to remember the build conversation. Bookmark the entity's canonical private `STATUS.md`: it tells you what period is complete, what needs action and where the evidence lives. Follow [ENTITY_RECORD](ENTITY_RECORD.md). GitHub stores the reusable code and process; it does not store your actual books or secrets.

To resume, give an agent that link and say: "Read this living record and the repo's START_HERE. Tell me the current position, reuse completed evidence, and carry out the next authorized action. Update this same shared record, verify it, and promote any reusable lesson into the process. Do not ask me to reconstruct the old conversation."

## Where things live

| Place | Use |

## Normal action: answer the exceptions

Ask the agent: "Read the current shared status and review queue. Show only the questions that need me, with proposed answers and the relevant evidence. Preserve the answers and verify worker acceptance."

Correct a provisional classification by referring to its stable review/transaction ID. Do not edit a worker snapshot or an old inbox file. Eligible routine proposals may apply after the agreed 72 hours, but unresolved assumptions remain revisitable. Silence does not teach a permanent rule and does not release integrity/historical/capital holds.

## If access or execution fails

1. Ask the operator to inspect the actual host's last run/log, current cloud snapshot and pending errors. An old "success" or a configured key does not prove a recent run.
2. For a genuine sign-in/MFA blocker, open the registered official portal and complete the private verification yourself. Give the agent the planned missing account/period batch while the session is usable.
3. The operator should verify the account and actual download before marking access recovered. Keep credentials/security codes out of chat and status.
4. If a posting timed out, inspect Zoho before retrying. Do not reset state or rerun blindly; duplicate financial entries can result.
5. After a Mac loss, use the saved backup key and verified cloud backup to restore a new offline copy. Review identity, integrity and history before activation. See [recovery contract](AUTONOMOUS_HANDOFF.md).

Codex need not stay open for an enabled LaunchAgent, but the relevant Mac user session and working power/network/Drive connection are needed. Confirm the actual installed schedule and successful unattended runs; a saved launch plan is not an active job.

## Finish a month or a year

- For a month: use [MONTHLY_CLOSE](MONTHLY_CLOSE.md); target the previous month by the following 7th. Ask for the short remaining list, not the setup checklist again.
- For tax time: use [YEAR_END_CLOSE](YEAR_END_CLOSE.md) and [CPA_TAX_HANDOFF](CPA_TAX_HANDOFF.md). Confirm cash/accrual basis, annual adjustments and allocations already applied. Request a factual one-page CPA brief and supporting reports.
- Before a new property, changed account, new personal use or refinancing: update dated context and review required adapters. Do not apply another property's rules by analogy.
